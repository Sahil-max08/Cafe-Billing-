1. Abstract / Executive Summary

Traditional college cafeterias and food courts often rely on handwritten slips or disjointed spreadsheets to manage daily counter billing. This manual workflow leads to long student queues during peak lunch hours, frequent calculation mistakes, unverified tax computations, lost transaction records, and an inability to track daily revenue or popular food items.

Campus Cafe is an end-to-end, lightweight, and self-hosted Cafeteria Billing & Point-of-Sale (POS) web application designed to solve these operational bottlenecks. Built using Python Flask and SQLite, it offers high-speed order punching, instant decimal-accurate calculations, configurable GST and discount logic, multi-payment tracking (Cash, UPI, Card), authentic 80mm thermal receipt printing, full menu CRUD with real-time stock toggling, and interactive sales reporting with Chart.js analytics.

Key Architectural Triumph
By enforcing strict backend recalculations via Python's Decimal module and storing immutable historical snapshots in bill_items, future menu price revisions will never alter past financial records.

2. Problem Statement & System Objectives

2.1 Problems in Traditional Cafeteria Management

  • Slow Counter Punching: Cashiers manually looking up prices, doing mental additions, and writing handwritten paper tokens cause long bottleneck queues.
  • Financial Rounding Errors: JavaScript floating-point errors (e.g. 0.1 + 0.2 = 0.30000000000000004) or manual calculation errors lead to unbalanced cash registers.
  • Price Mutation / Audit Loss: When a canteen raises the price of Samosa from ₹15 to ₹20, naive relational databases that link bills directly to the menu table retroactively corrupt past sales totals.
  • No Real-Time Stock Control: Kitchens frequently run out of high-demand items, leading to cashier punch cancellations and student frustration.

2.2 Core Project Objectives

Decimal Precision Engine

Guarantees tamper-proof arithmetic on unit prices, subtotals, GST, and discounts on the backend using Python Decimal(ROUND_HALF_UP).

Immutable Audit Snapshots

Preserves exact item name and unit price in bill_items at the instant of order completion.

Authentic Thermal Slip Format

Emulates an 80mm POS thermal printer with cafe headers, GST breakdown (CGST 2.5% + SGST 2.5%), barcode, and mock UPI QR code.

Real-Time Business Intelligence

Automated KPI calculation (Today's Revenue, Order Volume, Stock Counts) paired with Chart.js visualizations.

5. Functional Modules Specification

5.1 POS Billing Terminal (/billing)

The Point of Sale interface is optimized for high-volume transactions during cafeteria rush periods:

  • Category Filter Tabs: Categorizes food into All, Snacks, Meals, Beverages, and Desserts.
  • Search-As-You-Type: DOM-based sub-millisecond filtering across food names.
  • Dynamic Cart State: Automatic total, tax, and discount re-evaluation as quantities increment.
  • Discount Quick Presets: Rapid one-click discount buttons (₹0, ₹10, ₹20, ₹50) with subtotal capping.

5.2 Thermal Receipt Generator (/receipt/<id>)

Produces an authentic 80mm Point of Sale thermal slip:

  • Bilingual/Branded cafe header with address and mock GSTIN registration.
  • Split tax itemization displaying CGST 2.5% and SGST 2.5%.
  • Monospace alignment (simulating Epson/Citizen POS hardware) with serrated receipt border styling.
  • UPI payment verification QR code and machine-readable barcode mockup.
  • Embedded print stylesheet automatically triggering clean black-and-white printing.

5.3 Menu & Stock Management (/menu)

Provides full catalog CRUD (Create, Read, Update, Delete) with interactive modal dialogues and live stock availability switches. Kitchen staff can toggle items out-of-stock with a single click, instantly preventing front-desk cashiers from adding unavailable food to active orders.

5.4 Sales Analytics & Reporting (/reports)

Provides business intelligence for cafeteria managers:

  • Dynamic Periods: View metrics for Today, Last 7 Days, Last 30 Days, All Time, or Custom Date Range.
  • Interactive Chart.js Visualizations: Revenue & Order volume trends, food category contribution breakdown, and payment mode split (UPI vs Cash vs Card).
  • Top 10 Popular Items Table: Ranked list showing high-velocity menu items with quantity sold and revenue share.
  • CSV Export Engine: Download raw historical transactions for accounting spreadsheets.

6. Security, Anti-Tampering & Decimal Arithmetic

Why Decimal Precision is Critical in POS Software
Binary floating point representations (IEEE 754) used in standard programming languages cannot accurately represent base-10 fractions (such as 0.1 or 0.05). In a cafeteria processing 1,000 bills daily, rounding deviations accumulate into substantial discrepancies.

Campus Cafe eliminates floating-point drift by computing all monetary values using Python's decimal.Decimal library with banker's rounding (ROUND_HALF_UP): 

# Backend Calculation Engine (database.py)
unit_price = Decimal(str(menu_row["price"])).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
item_total = (unit_price * Decimal(str(quantity))).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
subtotal += item_total

# Tax & Grand Total Evaluation
taxable_amt = max(Decimal('0.00'), subtotal - discount_amt)
gst_amt = (taxable_amt * gst_rate_dec / Decimal('100.0')).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
grand_total = (taxable_amt + gst_amt).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)

Additional Security Safeguards:

  • Anti-Tampering Price Validation: Prices passed in POST requests from the client browser are disregarded. The server retrieves the verified price from the SQLite database.
  • SQL Injection Neutralization: 100% of queries use parameterized bindings (? placeholders). Direct string interpolation is strictly prohibited.
  • HTTP No-Cache Headers: Enforces Cache-Control: no-store, no-cache, must-revalidate to eliminate stale menu cache in shared browser terminals.
